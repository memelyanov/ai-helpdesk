## Requirement Completeness

- [x] CHK001 Are focus-management requirements defined for what receives keyboard focus when the trace dialog opens and when it closes? [Gap, Spec §FR-006] — *Resolved: FR-006 now states the dialog relies on native `<dialog>` behavior for focus-into-dialog on open and focus-restore-to-trigger on close.*
- [x] CHK002 Are keyboard-only interaction requirements defined for opening the trace control (e.g., via Enter/Space) rather than only "selecting" it? [Gap, Spec §FR-003] — *Resolved: FR-001 now requires the control to be a focusable, keyboard-operable element.*
- [x] CHK003 Are focus-containment requirements defined for keyboard navigation while the dialog is open (i.e., that focus cannot escape to the conversation behind it)? [Gap, Spec §FR-006] — *Resolved: FR-006 now states focus containment relies on native modal-dialog behavior.*
- [x] CHK004 Are screen-reader / assistive-technology requirements defined for the trace control, the dialog's content, and the "not reached" stage markers? [Gap] — *Resolved: FR-016 (dialog accessible role/name) plus FR-005's "more than color alone" requirement for not-reached markers.*
- [x] CHK005 Are visual-feedback requirements defined for a successful copy action (FR-009), beyond the failure-path behavior already specified in Edge Cases? [Gap, Spec §FR-009] — *Resolved: FR-009 now requires a brief visible confirmation on copy success.*
- [x] CHK006 Are requirements defined for the trace toggle's visual on/off state representation (e.g., that its current state must be visually distinguishable at a glance)? [Gap, Spec §FR-012] — *Resolved: FR-012 now requires the toggle to clearly indicate its current state at a glance.*
- [x] CHK007 Are responsive/small-viewport requirements defined for the trace dialog, beyond "never grows past the visible window"? [Gap, Spec §FR-008] — *Resolved: new FR-014 requires full usability (close control, scroll, toggle visibility) at any supported viewport width.*
- [x] CHK008 Are requirements defined for whether more than one trace dialog can be open at the same time, given each message is independently trace-able? [Gap] — *Resolved: new FR-013 states multiple trace dialogs may be open at once, independently.*
- [x] CHK009 Are requirements defined for preserving the conversation's scroll position when a trace dialog opens and closes? [Gap] — *Resolved: new FR-015 requires scroll position to be unchanged by opening/closing.*

## Edge Case Coverage

- [x] CHK024 Are behavior requirements defined for a browser that lacks native `<dialog>` modal support in production use (not just the test-environment fallback noted in research.md)? - [x] CHK025 Are requirements defined for extremely narrow viewports (e.g., mobile widths) where the dialog's internal scrolling (FR-008) and the trace toggle's visibility could conflict with limited header space?
